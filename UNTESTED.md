# Не проверено в игре

Всё ниже собрано и проверено только сборкой (`mvn package`) и ревью кода.
Игровой сервер на момент изменений выключен, ни одна из функций не
запускалась на живом сервере. Перед открытием сервера пройдите по списку.

## 0. Требования к серверу

- **Paper 26.3, Java 25.** Плагин собирается против `paper-api 26.3.build.259-stable`
  (class-файлы Java 25), в `plugin.yml` — `api-version: '26.3'`. На Paper 1.21.x
  и на Java 21 он не загрузится.
- Устаревшие (deprecated) API Bukkit (`ChatColor`, BungeeCord chat, `AsyncPlayerChatEvent`)
  по-прежнему работают, но при следующих обновлениях Paper могут исчезнуть.
- MySQL-коннектор обновлён до 26.10 (Dependabot #5) — проверьте подключение к БД при старте.
- Нужен сайт с PR `fix/plugin-contract`: `materialKey` в ответах плагину, защита от
  двойного возврата при ограблении, запас 10 мин у закрытия v1-заказов по ETA.
- Пароли БД читаются из `plugins/UnityLauncher/secrets.properties` (PR #2), не из jar.

## 3. Эта ветка

### Варианты товаров (#40, colorHex)
- Крашеная кожаная броня разных цветов — разные лоты (ключ: материал + зачарования + цвет,
  как `ShopChestItem` на сайте). Цвет уходит на сайт в синке магазина.
- Магазин выдаёт только стаки выбранного цвета. Некрашеная броня — без цвета.

### Фантом-доставка v1 (старые заказы)
- Контроллер теперь **включён** (раньше не создавался вовсе).
- Груз — **реальные стаки** купленного варианта из сундука продавца. Если их не хватает
  или сундука нет — недостающее создаётся простыми стаками (как раньше), в логе
  предупреждение. *Решение: застрявший оплаченный заказ хуже.*
- Заказ больше одной стопки доставляется целиком; при убийстве торговца выпадает весь груз.
- В сундук назначения не влезло / сундука нет — груз падает рядом, заказ закрывается
  как доставленный с `droppedNearby` (по контракту сайта). Раньше при отсутствии сундука
  заказ ждал подбора и при оффлайн-покупателе превращался в «ограбление».
- По прибытии груз выдаётся **даже если рядом нет игроков** (чанк назначения загружается).
- Состояние груза хранится в `plugins/UnityLauncher/phantom-cargo.yml`: рестарт не списывает
  сундук продавца повторно и не выдаёт груз второй раз.
- Застрявший курьер сообщает сайту `phantom-delay` (ETA сдвигается).
- Нераспознанный материал → заказ закрывается как ограбление (покупателю возврат),
  а не «доставлено» без товара.
- Отчёт об ограблении — **одна попытка** (повтор мог бы вернуть деньги дважды).
  Если он не дошёл, строка остаётся «в пути» на сайте — смотреть лог.
- Подобранный груз теряет служебные теги и складывается с обычными предметами.
- Отладочный лог по каждому тику выключен (`DEBUG = false`).

### Курьеры v2 (новые заказы)
Код курьера v2 из прошлого прод-jar в репозиторий не попал — написан заново по
`infra/phantom-courier-design.md`. **Без плагина сайт эти заказы не закрывает никогда.**
- У продавца `fleetSize` курьеров (если 0 — работает 1, в логе предупреждение),
  у каждого `capacitySlots` физических слотов.
- **Упрощение:** строка заказа не делится между заходами. Заход набирается целыми строками
  по очереди (FIFO по времени заказа), пока хватает слотов (`ceil(кол-во / размер стака)`);
  строки, которые не влезли, курьер ищет дальше по очереди. Первая строка берётся всегда,
  даже если больше вместимости («перегруженный заход»).
- Маршрут: сундуки-источники (ближайший сосед), затем каждый уникальный адрес доставки;
  следующий заход начинается с места окончания предыдущего.
- Позиция — функция времени по участкам маршрута (скорость как на сайте, 3,45 блока/с).
  Реальный торговец появляется только рядом с игроками, идёт к текущей точке; **без лодок**.
- Отстал от расчётной точки больше чем на 32 блока — сайту `delayed` (раз за заход).
- Выгрузка: сначала `trip-completed` по каждому заказу, потом `phantom-delivered` по строкам
  (`droppedNearby`, если не влезло в сундук — сайт берёт с покупателя штраф 70% от доставки).
- Убийство курьера: весь груз захода выпадает с тегами по строкам, исход решает подбор
  (покупатель — доставлено, другой игрок / деспавн — ограблено, возврат за товар).
  Ограбление частично доставленной строки возвращает всю её стоимость.
- Состояние груза — `plugins/UnityLauncher/phantom-courier.yml` (рестарт не списывает дважды).
  Позиции курьеров не сохраняются: после рестарта курьер начинает заход заново.

### Самовывоз (брони на авто-лотах)
- Каждые ~2 с плагин берёт брони с сайта и помечает в сундуке нужное количество
  (только в загруженных чанках). Сайт не присылает вариант, поэтому помечаются
  **первые свободные стаки материала** — зачарования/цвет/прочность не учитываются.
- Не хватает товара или слота под расщепление стака — предупреждение в лог, повтор каждые 2 с.
- Меченый стак: клик любого игрока отменяется; если кликнул покупатель и бронь не
  просрочена — плагин сам кладёт весь стак ему в инвентарь (без метки). Полный инвентарь —
  остаток остаётся помеченным в сундуке. Когда меток не осталось — сайту `collected`.
- Воронки, автосписание и магазин меченые стаки не трогают; фантом-доставка тоже
  берёт только свободный товар.
- Снятие меток: бронь исчезла с сайта или просрочена — на следующем опросе (если чанк
  загружен) или при открытии сундука. До первого успешного опроса после старта
  меченое заблокировано для всех.
- Известный риск: рестарт между забором и доставкой отчёта `collected` → сундук будет
  помечен заново, и покупатель сможет забрать второй комплект.
- Синк магазина с сайтом при простановке/снятии меток не вызывается — сайт увидит
  новые остатки при следующем закрытии сундука или pull-синке.

### Чат на карте (BlueMap)
- Каждое отправленное сообщение чата (не отменённое авторизацией) уходит на сайт.
- Сообщения с сайта рассылаются всем игрокам раз в ~2 с: `[Карта] имя: текст`
  (текст без интерпретации цветовых кодов).
- Если сервер упадёт между получением и рассылкой, сайт не переотправит эти сообщения.

### «Моё местоположение» на маркетплейсе
- Онлайн-игрок → координаты блока; оффлайн → ошибка `player_offline`.

## 4. Не реализовано (нужны решения)

- **Задания (tasks):** в плагине нет системы квестов; не определено, кто создаёт задания
  и какое событие в игре засчитывает выполнение. Награду плагин должен платить сам.
- **Переименование (`/plugin/users/:u/rename`):** нет триггера — ни команды, ни смены ника
  по UUID. Нужно решить, когда переименовывать и как синхронизировать MySQL плагина.
- **Wiki:** API только на запись; не определено, откуда в игре берётся содержимое
  (и нужна ли вики плагину вообще).
- **Лодки у курьеров** (из дизайн-документа v1/v2) — не реализованы.
